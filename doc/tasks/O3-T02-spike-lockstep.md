# O3-T02：Spike 逐条比对（L5 第一部分）

按 [`agent.md`](../../agent.md) 第 7 节格式，采用两阶段流程（[`O3-v1-plan.md`](../O3-v1-plan.md) 第 2.3 节）。**阶段一只写文档，阶段二必须等用户宣布冻结后才开始。**

## 目标

建立 B45 规定的 Spike 逐条退休比对，作为 L5 及以后每一级的门禁。本任务只做比对基础设施，不实现 CSR、异常或任何新的核内机制（这些是 O3-T03）。

已定的做法：

1. **进程内逐条比对**：把 Spike（`libriscv`）链接进 `sim/o3` 的 Verilator C++ 驱动。DUT 每退休一条指令，Spike 执行一条，立即比较；不一致时立即停止。不采用“分别跑完再比较日志”的离线方式，因为后续级的中断、MMIO 和外部事件需要逐条同步。
2. **固定 Spike 版本**：在 Alan 上从固定提交编译 Spike，安装到 `cislc-o3` conda 环境的前缀下；提交号、配置选项和编译命令写进 `sim/alan-env.yml` 或 `sim/o3/README.md`，可重现。Spike 配置为 `--isa=rv64i` 起步（随级扩展），内存布局与 `sim/o3` 的 AXI RAM 一致（`0x8000_0000` 起）。
3. **退休记录扩展**：`retire_info_o` 现在只有 PC、指令、rd、写回值（`sim/o3/check_trace.py:21–40`）。扩展为至少包含：每条退休的 PC、指令、整数目的寄存器与值、访存类型、地址、大小与数据（load 读到的值、store 写的值）、退休 lane。浮点、CSR 写入、异常 cause/tval 字段在类型中预留，由后续任务填充。字段随 ROB 项携带，按退休顺序输出；同拍多条退休按 lane 顺序逐条比较。
4. **比较内容**：PC、指令编码、整数写回（寄存器号与值）、访存地址/大小/数据。不比较时序。差异报告包含：周期、退休序号、双方的 PC/指令/寄存器值/访存信息，以及之前 32 条退休记录。
5. **程序来源**：
   - 现有 `sim/o3/tests/` 下全部整核门禁程序（含 `l3_branch_dense`）；
   - ACT4 生成的 RV64I 51 项（`doc/CISLC_O3.md:662` 所述）；
   - 新增一个仓库内的随机程序生成器（Python），生成 RV64I 用户指令序列：ALU、移位、分支（前向与后向，带有界循环）、JAL、load/store（地址限制在可缓存 RAM 的固定窗口内，自然对齐）、依赖链与独立指令交错；固定种子可重放，每个种子生成固定长度程序，以 `tohost` 结束。
6. **与现有 checker 的关系**：`check_trace.py` 的固定期望比对保留，Spike 比对是新增的独立门禁；两者都必须通过。

## 涉及模块

`sim/o3/`（C++ 驱动、`o3_tandem_top.sv`、Makefile、新随机生成器）、`rtl/core/o3_core.sv` 与 `rtl/backend/rob.sv`、`rtl/backend/backend.sv`、`rtl/common/o3_types_pkg.sv` 中与退休记录相关的字段与端口（只增加观测字段，不改变任何执行行为）、`sim/alan-env.yml`、`sim/o3/README.md`。超出范围先问。

## 阶段一（只写文档）

产出 `doc/spec/spike-lockstep-spec.md`：

- **Spike 版本与构建**：固定提交、编译选项、安装位置、`sim/o3` 的链接方式；Spike API 的使用方式（创建 `sim_t`/`processor_t`、加载程序、单步、读取寄存器与本条访存信息），附 Spike 源码文件与行号。若 Spike 的公开 API 无法直接取得“本条指令的访存地址与数据”，说明替代方法（例如 Spike 的 commit log 内部结构），不得自行修改 Spike 源码，需要时列为问题。
- **退休记录字段表**：每个字段的来源（ROB 项哪个字段、在哪一级写入）、位宽、有效条件；load 数据取写回值还是原始读数据；store 数据与 mask 的表示。
- **比较规则**：逐字段比较条件；x0、无写回指令、store 的处理；`tohost` 结束与超时规则；不一致时的输出格式。
- **随机生成器规格**：指令分布、地址窗口、循环有界性保证、种子与长度、如何保证程序在 Spike 上自身合法（不触发 Spike 端异常）。
- **门禁命令**：例如 `make -C sim/o3 run-spike-all`（全部固定程序）与 `make -C sim/o3 run-spike-random SEEDS=...`，以及默认种子数与长度。
- **测试计划**：比对器自身的正确性测试——人为注入差异（修改一条期望或在 C++ 中扰动一个寄存器值）必须被检出并报告正确位置；该注入只在比对器自测中进行，不进入门禁。
- **未决问题**：不得自行决定。

阶段一不修改 `.sv`、`.cpp`、`.py`、`Makefile`。

## 阶段二（spec 冻结后）

按冻结的 spec 实现；小步提交，每个提交 lint 通过。

## 闭环简化许可

本任务不实现 CSR、异常、中断、M 扩展；预留的记录字段输出无效值并注明由后续任务填充。随机程序不生成会导致异常的指令。

## 验收

- `scripts/lint.sh` PASS。
- 在 Alan 上，同一最终 SHA：
  - O3-T01 的全部现有门禁仍通过（`doc/spec/l3-closure-spec.md` §6.2、§6.3）；
  - 全部固定程序与 ACT4 RV64I 51 项在 Spike 比对下 0 差异；
  - 随机程序：至少 200 个种子、每个不少于 2000 条退休，0 差异；报告总退休条数；
  - 比对器自测：每类注入差异（PC、寄存器值、load 数据、store 地址、store 数据）都被检出且定位正确。
- 若比对发现 DUT 的真实错误：**停下报告**，附最小复现种子与差异输出，不在本任务中修 RTL；由用户决定是否另开修复任务。
- `doc/LOOP.md`、`sim/o3/README.md` 更新。

## 不做

CSR、异常、中断、M/A/F/D、RVC、MMU；任何改变执行行为的 RTL 修改。
